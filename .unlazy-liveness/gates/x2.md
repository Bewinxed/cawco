# Gates: X2 — arm the ingest ledger (integration gate, added by the parent)

D3 built and tested the whole receiving half of the §7 at-most-once guarantee, but the
producing half is unwired because the two call sites live in files D3 was forbidden to
edit. Today frames carry no provenance, so the hub admits everything and keeps no mark —
exactly today's behaviour, and the guarantee is inert. D3 named this as "the one thing
standing between the code and the guarantee".

Two wirings:
  1. packages/agent/src/harnesses/claude.ts:~1325 — the adopt subscribe holds event.seq
     and discards it. Stamp it.
  2. packages/agent/src/daemon.ts — reattachFrom(ackPayload, rows) has no caller; the
     register-ack handler is the natural one.

  CHECK: grep -c "srcEpoch\|\.line?.(" packages/agent/src/harnesses/claude.ts
  EXPECT: /^[1-9]/m
  EVIDENCE: `grep -c` -> 3 (the epoch read, its guard, and the stamp call). `adopt`'s subscribe (claude.ts:1330-1350) now reads
  `const srcEpoch = client.epoch` and calls
  `(ctx as Partial<SessiondAwareContext>).line?.(srcEpoch, event.seq)` one statement
  before `custody.ingest(event.data)` — `ingest` emits synchronously, so the stamp lands
  on that frame and no other, which is the contract stated at `SessiondAwareContext` in
  session.ts:84-100. Deviation from the shape D3 documented, deliberately: `client.epoch!`
  is NOT asserted. `SessiondClient.epoch` is `string | undefined` (it is `#welcome?.epoch`),
  and it is read per line rather than captured at adopt time so a client that ever
  re-welcomes stamps the epoch that is running now. Undefined means no stamp at all — an
  unstamped frame is the pre-ledger behaviour the honest-loss rule already covers, which
  beats a frame stamped with an epoch nobody minted. Import is `import type` (session.ts
  imports the harness registry, so a value import would close a module cycle);
  `bun run typecheck` -> all 7 packages "Exited with code 0".

- [x] G2: reattachFrom is called from the register-ack path
  CHECK: cd /home/bewinxed/cawco && grep -c "reattachFrom" packages/agent/src/daemon.ts
  EXPECT: /^[1-9]/m
  EVIDENCE: `grep -c` -> 2 (the call and the comment naming it), the call being in `takeCustody` (daemon.ts:385-411), called from the socket's
  message listener on the connection's FIRST `register` ack. The rows are real, not empty:
  a restarted daemon holds no sessions, so the hub answers its register with a `spawn` per
  session it wants running again (server.ts `restore`, sent immediately before
  `registerAck`), and those spawns are the only place this process learns a surviving
  child's cwd and sessionId — sessiond's `list`/welcome returns procId, pid, alive and ring
  head, and no cwd (core/src/sessiond.ts:86-93). So an adoptable restore arriving before
  the ack is held (`heldSpawns`), and on the ack it is offered to
  `supervisor.reattachFrom(ack.payload, rows)` instead of dispatched. Whatever sessiond is
  not holding comes back un-adopted and is dispatched exactly as before, as is everything
  if `reattachFrom` throws. `adoptable`/`custodyRow` are exported and unit-tested
  (daemon.test.ts, "custody off the register ack", 2 tests): claude-or-unset harness only,
  no bootstrap, no scratch, non-empty instanceId and cwd; `resume.sessionKey` becomes
  `sessionId`, absent becomes `null`. The window is that one ack — later `reannounce` acks,
  operator spawns and delegate spawns all go straight through — and an ack with no rows
  held returns before dialling sessiond at all.
