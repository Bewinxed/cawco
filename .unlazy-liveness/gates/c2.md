- [x] G1: behind/failed/pending render from frame data alone (unit tests over the derivations)
  CHECK: cd /home/bewinxed/cawco && bun test apps/dashboard/src/lib/cawco/ 2>&1 | grep -E "[0-9]+ fail" | tail -1
  EXPECT: 0 fail
  EVIDENCE: ` 282 pass` / ` 0 fail` (baseline 270 + 12 new in `convergence.test.ts`, no other
  cawco test file touched). Whole-repo `bun test packages/ apps/` → `706 pass / 0 fail`
  (baseline 689). New module `apps/dashboard/src/lib/cawco/convergence.ts` holds every
  reader, all pure and covered:
  - `buildConvergence(build, hubBuild)` → `'unknown' | 'current' | 'behind'`. Tested: a
    machine with `build.commit` undefined reads `unknown` even against a real `hubBuild`
    (the Mac's exact incident — `commit: None` must never read as current); a `hubBuild`
    that is itself absent (a hub older than A2) is *also* `unknown`, never `current`, so
    "nothing to compare against" can't masquerade as convergence; matching commits →
    `current`, differing → `behind`.
  - `fleetSyncFailures(fleet)` scans every `FleetItemState`-keyed category
    (mcp/marketplaces/plugins/skills/memoryDocs/hooks) plus the singular
    memory/memoryHook rows, returns only rows at `state: 'failed'` with their `detail`
    verbatim — `applied`/`removed` rows are left out (tested). The hub's own copy for the
    incident (`edited on this machine — adopt it or overwrite`) round-trips unmodified.
  - `fleetSyncAgeMs(fleet, now)` — ms since `fleet.at`; `undefined` for a machine that has
    never synced (tested against an 11-day gap, the exact number named in the brief).
  - `deployInfoOf(deploy)` / `isDeployDiverged` / `isDeployNoteworthy` — structural reader
    over C1's `DeployTick.state.kind` vocabulary (mirrored as a local `DeployKind` union
    since packages/agent is out of scope and C1's own G3 says the wiring onto the hub
    frame is left to "leaf C2 subscribes there" — not yet landed by any leaf). Reads
    `undefined` off anything not shaped like `{kind: string}` — the same "hub predates
    this field" shape `pulses`/`hubBuild` already use in client.svelte.ts. `unmarked` and
    `current` are not noteworthy (an ordinary dev tree is not a fact to flag); every other
    kind is, and `diverged` is flagged apart as the one that must read as a refusal, not a
    stale badge.
  `client.svelte.ts` gained `state.hubBuild` (folded from `frame.hubBuild` on the
  `instances` frame with the exact same structural cast `pulses`/`handoffs` already use —
  additive field, absent from a hub that predates it) and a `cawco.hubBuild` getter.
