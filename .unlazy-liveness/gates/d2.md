  Two things are quotable there: the CLI anticipates a re-`initialize` (it has a dedicated
  "is already registered" path for MCP servers it has seen before), and it branches on a
  prior-initialization flag (`let qe=!u`) for a one-time side effect rather than refusing.
  That is *suggestive* that a second `initialize` would be accepted — and it is not
  sufficient. It says nothing about the SDK client half (a fresh `Query` initializing
  against a child mid-turn, with queued commands and parked control requests), which is the
  half that would actually have to hold. Betting 45 live sessions on an inference from a
  minified bundle is not a trade this leaf will make.
  Verdict recorded, per the gate's own terms: **custody + boundary hand-off ship**, one
  graceful respawn per session per agent restart, at a turn boundary. Adoption stays
  available as a later, cheap upgrade: it would remove the respawn and change nothing else
  in this leaf's design, and it needs a live spike on a machine with no real sessions on it.
  Time spent: inside the 90-minute box.
