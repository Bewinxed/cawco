# Gates: D5 — opencode server under sessiond

Scope: packages/agent/src/harnesses/opencode.ts (+ its tests). Design §4.2: `opencode serve`
as a sessiond spec-child, announced port read agent-side from the ring,
`createOpencodeClient` attach, SSE re-subscribe on supervisor rebuild; no event ring for
opencode (the server is its own event authority). If the opencode SDK surface has moved
since the design read (1.18.18), ABANDON with the observed surface quoted rather than
forcing it.

SDK surface re-checked before building, NOT moved: `@opencode-ai/sdk` 1.18.18 in
packages/agent/node_modules still exports `createOpencodeClient(config?: Config & {directory?: string}): OpencodeClient`
(dist/client.d.ts:5) and `Config.baseUrl` (dist/gen/client/types.gen.d.ts:10).
Port announcement verified LIVE against the installed binary (opencode 1.18.19),
`opencode serve --hostname=127.0.0.1 --port=0` stdout:
    Warning: OPENCODE_SERVER_PASSWORD is not set; server is unsecured.
    opencode server listening on http://127.0.0.1:43663
— parseable, and parsed by the SDK's own rule (startsWith "opencode server listening",
then /on\s+(https?:\/\/[^\s]+)/). No abandon.
