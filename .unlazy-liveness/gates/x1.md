- [x] G4: root cause named in the report (which state, which direction it leaks)
  EVIDENCE: packages/agent/src/usage-limits-backoff.test.ts's `mockFetch()` helper
  reassigns `globalThis.fetch` on every test (and in `toCleanState()`) but never
  restored it — no `afterEach` reset. Bun runs every test file of a `bun test`
  invocation in one process sharing one `globalThis`, so once this file ran, the
  process-wide `fetch` stayed pinned to whatever canned `Response` its *last*
  test installed (`mockFetch(() => new Response('{}', { status: 500 }))`, from
  "non-429 failures cool down a fixed 2m"). Direction: packages/agent leaks into
  packages/hub — presence.test.ts, truth.test.ts, and instance-titles.test.ts all
  call the *global* `fetch()` against their own `.listen(0)` server
  (`fetch(\`http://localhost:${port}/api/agents\`)` etc.); with the mock still
  installed, that call never reaches the real server and the mocked 500 response
  is what `expect(response.status).toBe(200)` saw. Isolated bisection that
  confirmed it: `bun test packages/hub/src/presence.test.ts packages/agent/src/<file>.test.ts`
  for each of the 10 agent test files — only `usage-limits-backoff.test.ts` paired
  with presence.test.ts reproduced the failures (5 fail); the other 9 agent files
  paired clean (0 fail each). Fix: capture `const realFetch = globalThis.fetch`
  at module load and restore it in `afterEach`.
