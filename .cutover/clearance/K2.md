## For a consumer set: how to clear a no-restyle hit

Each kit part gained axes in its recipe (`tv`, in the part's module
script). A consumer passes the axis as a prop and drops the classes the
value draws; its other classes stay in `class`. The table under "Sites" says,
for every appendix site, the props that replace its flagged classes, what
stays on the consumer, what the consumer drops because the part already
draws it, and the hooks.

```svelte
<!-- before -->
<Button class="text-ink-muted max-phone:hidden" variant="ghost">
<!-- after -->
<Button class="max-phone:hidden" tone="muted" variant="ghost">
```

A class the table lists as a **hook** is a name another file's selector or
script reads (`rail-configure`, `count`, `session-tabs`, `hosted`,
`strip-hit`, `rollout-chip`). It is no utility, but rules read it, and at T
some of them drew the element. "Hooks: what read them at T" below lists each
rule, what it drew, and where that look lives now: a kit value the set passes
(`count` → `figures="tabular"`, `rail-configure` → `current="selected"`),
the consumer's own classes, or the consumer's own rules, which the set keys
on the data attribute it gives the element in the class's place (delta O2;
`count` and `session-tabs` already have the hook sweep's flags,
`data-text-section-count` and `data-session-tabs`). The class goes once its
look has a home.

Where a class a set adds in its own kind-5 work belongs to a part's look,
the value carries it (Spinner `reveal="glyph-busy"` carries set 8's
`group-not-glyph-busy:animation-paused`).

## The proof

`bun .cutover/k2-sites.ts` reads every appendix site from the consumer's
own markup: each element of the part whose class reads a string on the
reported line (a constant several elements share included), every string
the class can be (each ternary branch, `&&` with and without its right side,
`cn()` arguments), and the element's other attributes. It writes
`K2-sites.json`.

`bun .cutover/k2-exact.ts` then takes each element and each of its class
strings. Today is `cn(<the part's own cn() arguments before its looks>,
recipe(<the element's props>), <the consumer's classes>)`. New matches the
flagged classes to one value per axis whose classes are exactly them, and
is `cn(<the same arguments>, recipe(<props> + <the values>), <the other
classes>)`. The recipes are the kit's own `tv({…})` literals built with
utils.ts's `tv`, and `cn` is utils.ts's, so the merge is the kit's
tailwind-merge. The two compare as class sets (a class attribute's order
draws nothing). It writes `K2-exact.json`, which this file's site table is
generated from.

    256 sites (260 elements, 266 class strings), 0 mismatches, 0 unmatched

The Chromium check is now part of the look proof. A class string can be
right and still draw wrong: a guard can read an ancestor the page never
has, and a T rule's shorthand can set a longhand no class names. So
`bun .cutover/k2-looks.ts` draws each guarded look and each hooked element
in Chromium, T against today, and compares what they compute ("The looks in
Chromium" below). Both proofs run for every K2 change.

Two sites are modelled as they truly run: HookTester.svelte:50's three `&&`
branches are mutually exclusive (`kind` is one value), so its three real
strings are checked rather than the evaluator's eight combinations; and
DelegateTypeEditor.svelte:286 passes its class through `ModelCombobox` to
that component's Button (`variant="outline"`, `justify-between gap-2` first).
That site's Button look (`width="capped"`) reaches the Button only if
ModelCombobox.svelte (set 7's file, unchanged here) takes a `width` prop
and passes it on: needs ModelCombobox `width` → Button `width`, set 7.

## Variant order (house/variant-order, V.md)

`bunx eslint src/lib/components/ui src/lib/components/features/ProviderLogo.svelte`
had 54 `house/variant-order` problems, 39 distinct pairs. V.md listed 15;
the other 39 came from K2's own looks meeting their parts' classes. It now
has 0. Each pair's winner comes from the source of record, main at T
(`git show ac7b79de8:<file>`):

- Where both classes stood in the kit's markup at T, Tailwind's current
  winner is the source's, and the loser takes its negation.
- Where one class came from a consumer's `<style>` at T through a K2 look,
  that rule was unlayered, so it outranked every kit utility: the look
  wins. A kit class is shared by every caller, so the look is split

### Guards: negate the whole condition

A guard added to make two states exclusive must not change either state
alone. So it negates the whole condition, which holds when the ancestor is
absent: `not-group-…`, `not-peer-…`, `not-in-…`. `group-not-…` and
`peer-not-…` instead require the ancestor and negate only its state; they
are right only where the source selector itself required that ancestor.

- 15df096ed wrote Checkbox `reveal="card-pick"`'s ten field guards as
  `group-not-data-[disabled=true]/field:`. The board has no `group/field`
  around a card, so every showing state failed and the pick boxes never
  showed. They are `not-group-data-[disabled=true]/field:` now.
- Switch's right-to-left thumb guard was `group-not-data-[size=…]/switch:`;
  it is `not-group-data-[size=…]/switch:` now (no computed change: the root
  always carries `data-size`, so its thumb is inside the group).
- Spinner's `group-not-glyph-busy:animation-paused` stays: its source,
  RolloutChip's `[data-slot="glyph"]:not([data-glyph="busy"]) >
  [data-for="busy"]`, required the glyph cell.
- Every other guard in f89c35672 and 15df096ed negates the element's own
  state (`not-aria-expanded:`, `not-aria-invalid:`, `not-disabled:`,
  `not-has-…`, `not-data-…`, `not-status-ahead:`, `not-active-…`,
  `not-[[data-variant=legend]+&]:`, `not-nth-last-2:`,
  `not-aria-pressed:`), which needs no ancestor. DropdownMenuItem
  `marks="current-busy"` adds no guard: its `aria-current:` forms contain
  the destructive states they outrank.
