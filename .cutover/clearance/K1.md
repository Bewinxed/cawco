# K1: the table parts' variants

The recipes are `tv` in each part's `<script module>` (src/lib/components/ui/table/): `tableCellVariants`, `tableHeadVariants`, `tableRowVariants`, `tableVariants` (slots `container`, `table`). With no variant passed a part draws its base, as before.

A consumer site passes the props below and drops exactly the classes the appendix lists for it; every other class it passes stays on it. `bun .cutover/k1-exact.ts` proves each site equal to today, case by case (both branches of every conditional).

### 2. ViewRoutines.svelte:922 and :974: STOP

- **Part:** `<Table.Row>`.
- **Classes:** `band border-0`.
- **Conflicting rule:** `shadcn/no-unknown-classes` in the kit file.
- **Attempt:** a `ledger-band: "band border-0"` value in `tableRowVariants`, linted, then reverted. `bunx eslint src/lib/components/ui/table/table-row.svelte` gave:

  > `11:24  error  "band" is not a class this project's Tailwind knows, so no CSS is generated for it. Fix the spelling, or declare it with @utility in src/app.css. … shadcn/no-unknown-classes`
  >
  > `✖ 1 problem (1 error, 0 warnings)`

- **Why ViewRoutines may write `band` and the kit may not.** The rule (`@shadcn/lint` 0.2.1, `dist/index.js:5042`) admits a non-Tailwind class only if the same file's `<style>` declares it: `const ownClasses = isSfc(filename) ? styleClassesOf(context.sourceCode?.text ?? - **The ways to admit it are all outside K1, or a rule that draws nothing:**
  - `@utility band` in src/app.css;
  - an `allow` entry in eslint.config.mjs;
  - an empty `.band` rule in the kit file.
- **Proposal for set 4.** The hook's row rule paints `background: var(--surface-band)`, which is what `variant="band"` (`border-0 bg-surface-band`) draws. Once set 4 moves the `tr.band th` look onto the heads, those rows take `variant="band"` and the hook class goes.

**Checked and not gaps:**
- **Many or few items:** a table body with 0, 1 or 3× rows lays out as rows; the kit has no flex row or card grid to wrap.
- **Images, inputs, hover:** the kit table files hold no image, text field or hover style. Buttons are the consumers'.
