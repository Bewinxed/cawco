## Variant order

variant order: src/lib/cawco/routines/RoutineDetail.svelte:259 hover:text-link-ink under group-outcome-failed/run:text-status-fail-ink. At ac7b79de8 both rules sit in RoutineDetail's own scoped `<style>` (one layer), so specificity decides: `.runs-ledger :global(tr.run[data-outcome="failed"] .result)` (0,5,1 with Svelte's scoping class) beats `a.result:hover` (0,3,1), and a hovered failed run stays fail-ink. V.md as re-adjudicated (cawco/fdd881b4 @ 125f01453) lists this pair with Tailwind's winner only; the source winner is the failed rule. The loser is now `hover:not-group-outcome-failed/run:text-link-ink`. Guard form: `not-group-…` (the whole condition negated), compiled by Tailwind 4.3.3 as `.hover\:not-group-outcome-failed\/run\:text-link-ink:hover:not(:is(:where(.group\/run)[data-outcome="failed"] *))`, so it holds with no `group/run` ancestor; the source's `a.result:hover` did not require `tr.run`, so `group-not-…` (which needs the ancestor) would be wrong here. This is the only guard set 4 wrote; `group-not-first/row:` on the ledgers' cells is K1's `rule="between"` recipe, not a guard. The stacked `hover:group-outcome-failed/run:text-status-fail-ink` is deleted: the source had no combined rule, and with the states exclusive `group-outcome-failed/run:` alone covers that case.

Also on that line: the source sets `text-underline-offset: 3px` only under `a.result:hover`, and the markup had `underline-offset-(--offset)` at rest (3px instead of `auto` there). It is now `hover:underline-offset-(--offset)`.
