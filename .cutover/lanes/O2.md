## needs size token (same shape as O1)

- needs size token: --tray-chip-min: 120px (DelegateTray.svelte:1852; source `.chip { min-inline-size: 120px }`)
- needs size token: --tray-chip-max: 224px (DelegateTray.svelte:1853; source `.chip { max-inline-size: 224px }`)

Why: `fly()` deep-clones a finished chip, appends the copy to `document.body` and rewrites its inline style (`copy.style.cssText = "position:fixed;…;inline-size:${from.width}px;…"`). Under the literal rule the chip's 120px floor and 224px cap would live in inline custom properties, and the copy would lose them. Before the cutover the copy kept `.chip`'s class rule, so it stayed clamped to 120–224px. That clamp is visible when the tray is drawn scaled (the script reads `layoutScale`), because `from.width` is a scaled box. No existing token holds either value, and a length literal in a residual or a rem-based numeric utility breaks the lane rules. So the chip's floor and cap read its own inline values first (`--floor`, `--chip-max`), and the declared tokens second.
- Live chips compute exactly as before, now.
- The flying copy is clamped exactly as before once integration adds the two tokens. Until then it computes `min-width: auto` and `max-width: none`, so the clamp is missing, and visible, only on a flight from a scaled tray.

## Mechanism decisions (Opus lane, delta I)

- Rail rows and nested transcripts. Subagent's `.branch :global(*)` (the rail reset on every descendant) stays foreign-dom: it is a custom property on each descendant, rendered by ToolGroup, MessageRow and the rest, and inheritance from the root would lose to rows that publish their own. Delegate's `.delegate :global(.bhead)` reached every head under the card, including a nested Subagent's (InlineTranscript renders Subagent and Delegate). The card's own head takes the utilities; the nested heads' extra `flex: 1 1 auto; min-inline-size: 0` stays a foreign-dom residual on `[data-slot="rail-row"] :global([data-slot="rail-row"] [data-bhead])`.
- Head hover and chevron turn use named groups (`group/bhead`, `group/trow`, `group/cmd`, `group/chip`, `group/hitl`, `group/body`, `group/qopts`, `group/report`), so a nested card's head never answers an outer one. The chevron turns with `transform-(--chev-turn)` (`--chev-turn: rotate(90deg)`), not `rotate-90`: the source turned `transform`, and its transition is on `transform`.
- Permission card's Peer Rule. The kit Button merges classes with twMerge built from the theme's own keys, so `border-status-done-ink bg-surface-recess hover:bg-surface-recess` (and the fail-ink twin) replace the secondary variant's border, fill and `hover:bg`, and every state the card reaches computes as the old unlayered rule did. `.choice > *` set `flex: 0 0 auto` over the peers' `flex-1`, so the peers carry `flex-none`; the old `flex-1` never computed. The `grant`/`refuse`/`peer`/`btnBase` strings stay in the script, unchanged, because the `data-prompt-grant`/`-refuse` hooks read them; `primary` and `dismiss` had no use left and are gone.
- Prompt's title-row margins: `.place + .minimize { margin-inline-start: 0 }` is `peer/place` on the Kbd and `peer-data-num/place:ms-0` on the Button (the Kbd always carries `data-num`).
- The question rail's height is `block-(--rail-h)` (writes `block-size`), so its `block-size` transition still fires.
- Mark hues: `m{N}` classes became `style:--mark-bg="var(--mark-N)"` with `bg-(--mark-bg)`, the same computed colour without eight variants.
- `font-family: inherit` on ToolGroup's rows was dropped: preflight gives every button `font: inherit` and base sets no button font, so the computed value is the same.
- Kit components: utilities passed through `class` to Input (`h-c-btn-h-sm` replaces the kit's `h-9` in twMerge), Badge, Button, Kbd, Spinner and icons; the dropdown item's `[&_svg:not([class*='size-'])]` skips a sprite that names its size. Shot takes no `class`, so the thumbnail and gallery rules stay foreign-dom with `:global`.
