### New

- Projects, each led by Caw. Pick a template on New project and Caw sets it up with you in a thread. Talk to him in his dock beside the project page. With Caw on, he also acts when something happens in the project; with Caw off, he only answers you
- Caw can run commands, edit files and change settings in his project's folder, inside a sandbox, and every call shows in his thread. Anything outside a short safe list waits for you on an Approve card showing the exact command
- Tasks are full trackers: comments, your own fields, search and filters, archive, and a history of who changed what and why. A task's sheet shows what its attempt produced, report first, with Try again. A folder that isn't a git repository can run tasks too, and nothing is pushed anywhere
- Routines run a session on a schedule, and GitHub events such as pull requests and issues can start them. A run with nothing to say stays quiet
- Connections keep an outside service's key on the hub, so sessions can use the service without seeing the key. Webhooks reach a project through one signed public path (`cawco relay on <project>`), and an action a session schedules, such as a post, runs only after you approve it
- More than one account per provider, for Claude, OpenCode and pi, in Configure › Accounts. Your existing logins move in without signing in again. A session that hits its account's limit moves to one with room and carries on as the same session
- Usage shows each account as a dial, the 5-hour window inside and the week outside, with how long until you're stopped and which account takes over next. Spend now shows only on the Spend and usage pages
- Artifacts: previews, decision pages and drawings an agent makes are kept by the hub and open in their own tab. Pin comments and pen marks on them and they reach the session by themselves. You can draw in the composer too, with the pen or ⌘⇧D
- Attach any file to a message, up to 100 MB
- An agent's question or permission request opens in the composer the moment it's asked. Choose Other to type your own answer, answer from the keyboard, and come back to it after an update or restart
- Start a session for a project on a machine that doesn't have it yet: Move & start copies the project over after you confirm
- Pause a machine until a set time from its menu. Waiting work starts in order when the pause ends
- Continuing a session in a new one brings its delegates, queued work and open questions along

### Improved

- Updates check the new build for a minute and roll back if it isn't healthy. A running turn carries on through an update, and open tabs reload onto the new build where you were reading
- A message is never lost when a session's process restarts, crashes or sleeps. A message to a busy session is read within seconds, and the command it was running carries on in the background
- Caw's head in the top bar counts what needs you and opens one panel of approvals, questions and update notices. Alerts about a session you have open wait instead of buzzing your other devices, and answering one clears it everywhere, Telegram included
- Permission requests say who is asking and show the change before you choose. API keys and tokens in them are hidden on every screen
- Session tabs are folder tabs with a status rim, and you can drag them to reorder. Switching tabs is quicker, and two panes cost no more than one
- On a phone the top bar is one slim row, with Search and your machines in the sidebar
- Jump and @ in the composer search every machine's sessions and threads in one ranked list
- Open the composer's history with ↑ in an empty composer, or hold the composer on a touch screen. The clock button is gone
- Sign a machine in with Log in… in its dashboard menu, which runs Claude Code's own login there. `cawco login` and `--token` are gone
- On a Mac, privacy permissions go to one entry, CawCo Agent, and survive updates. Remove the old "cawco" entries once with the − button in Screen Recording and Accessibility
- Changes to fleet MCP servers, skills and plugins reach running sessions within seconds. MCP sign-in works from any device
- OpenCode works with every model, and MCP tools load only when used, so a large tool set no longer fills the model's context
- Delegates run in sandboxed workspaces that clean themselves up after they finish, keeping any work that never landed. Their reports open with a one-line headline
- A message that couldn't be sent says why and offers the fix, such as signing in or Send again
- "Side quest" is now "Spin off", and discarding a spin-off keeps its work

### Fixed

- A message sent in the last second of a turn is no longer lost, and sending no longer collapses the transcript
- A session keeps the effort you chose through a crash, restart or account move
- Switching between many tabs no longer slowly eats memory, and menus no longer swallow the click after they close
- Push notifications never show what you typed, and tapping one opens its session
- A machine that runs out of processes refuses only the session it can't start, and on Linux a runaway session stops inside its own limit
- Every key and token the hub stores is encrypted on disk
- A Mac no longer reports its own name as in use because of the hub
