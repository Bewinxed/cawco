# Projects P1 — build slices

Spec: `2026-10-06-projects.md` (§5.1 project shape, §5.2 tasks/stages/views, §5.3 running work, §6, §7 P1).
Words: WORDS.md (project, place, workspace, task, stage, kind, to-do, plan, attempt, view, delegate type).
UI: DESIGN.md is law; tokens from `design/tokens/cawco.tokens.json`.

## Rules for every slice

- No unit tests (owner rule). Verify with the root `bun run typecheck` (includes `openapi:check`), `bunx biome
  check` on changed files, and by running the hub against a scratch data directory and calling the routes.
- A route or response shape change: `bun run openapi` in `packages/hub`, commit `openapi.json`. Routes only the
  dashboard uses are fine; routes nothing outside the hub calls use `hidden`.
- The apple app reads `GET /api/projects` with `id`, `name`, `machineId`, `cwd`, `createdAt` required: keep them
  (the primary place) and only add fields.
- Migrations follow the repo: `drizzle-kit generate` against the latest snapshot, or hand-written SQL with a journal
  entry, applied at hub start. Existing rows migrate; nothing is dropped.
- One commit per slice on the current branch, message ending with the session's attribution lines. Do not push.

## Slices

1. **Project identity and places.** `projects.remote` (normalised origin URL, nullable); table `project_places`
   (project, machine, path, kind `checkout` | `workspace` | `hub`); every existing project becomes one checkout place.
   Adding a folder whose remote matches a project adds a place instead of a new project. Delegates inherit their
   parent's project and their workspace becomes a `workspace` place while it lives. `GET /api/projects` adds
   `remote` and `places`. Dashboard membership (`projectsFor`) matches any place; the project page lists places.
2. **Hub folder.** A git-versioned folder per project on the hub, created on first use, with §5.1's layout; a file
   API (read, list, write, commit with a message) with path safety; writes are commits.
3. **Tasks as files.** §5.2's task file (frontmatter + sections + nested to-dos), parser and writer, an index table
   rebuilt from files by hash, REST for the dashboard, MCP tools `task_create`, `task_read`, `task_update`,
   `task_link`, `todo_write` by role. Tracker setting per project (`cawco` now; GitHub later).
4. **Stages.** `stages.md` with the six kinds, moves and who may make them, hooks (`runs`, `until`, `after`, `by`);
   templates (code, social, outreach, SEO, design); the Needs-you lane derived, never a stage.
5. **Dispatcher, part 1.** Frontier (kind `todo`, every `after` landed), an attempt = a work item in the task's
   workspace, edges (blocked waits), caps and backpressure, the landing result moving the task to its done stage.
6. **Tasks surface.** Dashboard Tasks with board (Pragmatic drag and drop) and table views, a task drawer with to-dos
   and attempts. DESIGN.md recipes.
7. **Dispatcher, part 2.** Fresh retry in the same workspace, group join, file ownership, non-commit outputs,
   budgets, lead authority; `lands: main | branch | pr`.
8. **Follow the project.** Project delegate types from `delegates/*.md` (shadow fleet types); project skills and MCP
   reach every place (the hub sends each machine the cwd); the plan ↔ to-do link; OpenCode deny settings; `type:`
   on tasks.
